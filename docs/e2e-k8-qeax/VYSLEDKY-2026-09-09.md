Kandidát: rozšířit bootstrap o založení/opravu receptions.
- **N-K8-2 — chybný název vazební tabulky (`t_secuser_group` → `t_secusergroup`), OPRAVENO.** Vrstva 2 (`E_ADDIN_ACCESS`) do 9. 9. nikdy neprošla na skutečné security: dotaz na členství selhal, EA nevrátila výjimku ale výsledek bez `<Dataset_0>` + modální dialog, bridge to vzal jako „žádné skupiny" → fail-closed read i pro člena. Harness to nechytil (mock odpovídal na regex `t_secgroup`). Oprava: název tabulky + detekce chybějícího datasetu → důvod „SQL selhal" místo „není členem"; 2 nové testy (grep zdroje + mock bez datasetu). Poučení: jména tabulek ověřovat živě, ne z paměti; K3-typ recon (`sqlite_master` / `INFORMATION_SCHEMA`) patří do bankovního postupu (NAVOD 6.3).
- **N-K8-3 — audit se ukládá do PRVNÍ package jménem `#AI-LOG`, ne do té zamýšlené.** `FB_Audit` hledá `SELECT ea_guid FROM t_package WHERE Name = '#AI-LOG'` bez ORDER BY → v QEAX (3× `#AI-LOG`) skončilo všech 18 dnešních artefaktů v `/Groups/#AI-LOG` (356, pilot RB), nikdy v 686. Navíc audit je **zápis do modelu, který vrstva 2 nehlídá** — i odmítnutá dávka nečlena (A2w) audit zapsala (a v bance by u uživatele bez práv k package `#AI-LOG` padla na EA security → dnes best-effort warning). Kandidát (nutný před bankou, kde je `#AI-LOG` jméno běžné): cíl auditu podle GUID z configu (`FB_Config.auditPkg` nebo položka whitelistu), fallback jménem jen s ORDER BY + warning při >1.
- **N-K8-4 — `E_SQL` na `GROUP BY … HAVING` (K3c) a na `SELECT * FROM t_seclocks` s 0 řádky (K10).** První je skutečné omezení EA SQLQuery (dialog vyskočil, zbytek dávky správně `skipped`). Druhé: v A4 týž dotaz prošel s 1 řádkem; s 0 řádky přišlo `E_SQL` — buď EA při prázdném `SELECT *` vrací výsledek bez `<Dataset_0>` (pak je detekce E_SQL z 8. 9. falešně pozitivní na prázdných výsledcích `SELECT *`), nebo dialog vyskočil i tady. Rozhodne odpověď Miloše (dialog ano/ne) — **zapsat do PROTOKOL-EAFB §7 E_SQL jako otevřený bod**, ověřit v bance krokem 6.3 (dotaz na prázdnou tabulku).
- **N-K8-5 — chování dialogu Manage Add-Ins v security modelu:** sloupce Available Add-Ins / **Groups** / Status / Load on Startup; Status **Optional** = add-in přiřazený skupině, uživatel si ho zapíná sám; `t_xrefsystem` pak nese `GroupSettings` (Client = GroupID) vedle `UserSettings`. Osiřelý `UserSettings` řádek na GUID smazaného add-inu zůstává (EA neuklízí) — pro audit správce = filtrovat JOINem na `t_object`.
- **N-K8-6 — Group Lock jako admin:** aby správce nastavil (a odemkl) skupinový zámek na skupinu, musí být jejím členem; postup „přidat se → zamknout → odebrat se" (Miloš). `t_seclocks`: `UserID, GroupID, EntityType='Element', EntityID = GUID package, Timestamp`.
